**问题**：最初只有「日程冲突检测」一个功能，用户提出要加「目标规划」和「动态反馈重规划」。

## 迭代 4：大模型配置面板 + 语音输出

**问题**：LLM 接入之后，「谁的 Key、花谁的钱」变成真问题；同时用户要求助手能出声。

**用户 Prompt 链**：
> 所以以后所用用户都用我的钱是吗，或者弄个接口自己配置自己的
> 你在页面弄啊弄个配置的供应商模型url还有apikey还有请求头。
> 原来的模型怎么发声音，我记得可以用免费的本地模型

**AI 输出**：

1. 判定为 BYOK（Bring Your Own Key）：Key 只存浏览器 localStorage，每请求临时透传，服务端不落盘、不写日志；自填 URL 只允许公网 https，挡内网探测。
2. 配置面板补齐 5 个字段：厂商 / API Key / 模型名 / URL / 额外请求头（`Key: Value` 逐行）。
3. 朗读改为系统自带 TTS（免费离线），自动挑中文音色，加右上角总开关 + 每条消息 ▶ 重听 + 长句分段，解决 Chrome 念长文中断。

## 迭代 5：修 Bug —— 长期目标存成整句

**问题**：用户实测发现「你好啊，我想当科学家」被原样写进长期目标。检测用的是关键词，但存进去的是原句 `t`，两个变量不是同一个。

**用户 Prompt 链**：
> 有个 bug，我输入"你好啊，我想当科学家"，直接把原话放进长期目标了。只留目标本身：上面那句最后存的应该是"成为科学家"，不是原话
> 语言逻辑是什么样子的

**AI 输出**：把「检测」和「抽取」拆成两步，重写 `extractGoal()`——剥寒暄 → 锚点词截断 → 去时间/连接词 → 动词归一（当/做 → 成为）→ 去语气词 → 长度护栏 → 情绪/当天事挡在门外。随后在浏览器里逐句实测 7 种说法，全部符合预期；并故意造了「我想哭」「我明天想去图书馆」两个反例，确认不会被误存。

## 迭代 6：记忆分三层 —— 长期 / 聊天 / 日记

**用户 Prompt**（一次给全三条约束）：
> 做记忆分层，分成长期记忆和聊天记忆和日记。长期记忆要符合软件优势，聊天记忆短一点主要是上下文不太突兀。日记主要是每次聊完存一行"日期：摘要"，平时不掺和，超过 3 天没来，翻日记上次你说要考试，后来怎么样了

**设计判断**：记多了像监视，记少了每句从零开始。所以三层各管各的，且用「保留时长」划边界：

| 层 | 保留 | 谁用 |
|---|---|---|
| 长期记忆 = profile | 一直在 | 计算器输入，只有明说才写 |
| 聊天记忆 | 3 轮后滚掉 | 接住「就那个」「三点」 |
| 日记 | 一行摘要，最多 180 行 | 隔 3 天以上回来才翻 |

**AI 输出**：三层落到 `DATA.memory`，日记按「目标 → 排了什么 → 那会儿的状态」拼摘要，不存原话；同时补了「半句接龙」（问过几点后只答「下午三点到五点」也能进时间轴），并在画像页加了记忆卡可查各层条数。

**实测**：「我要考试」→ 追问时间 → 「明天下午三点到五点」→ 补成 15:00-17:00；聊完 5 轮聊天记忆稳定 6 条，日记落成 `10月24日：想成为科学家，排了考试 15:00-17:00，那会儿很累`；把日期调到 4 天前，开场即「上次（10月20日）你说想成为科学家，后来怎么样了？」
